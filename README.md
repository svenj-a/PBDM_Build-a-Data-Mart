# PBDM - Project: Build a Data Mart
-- Developing a DB for a booking platform following the example of Airbnb --

## What This is About
In this project, a relational database for an accommodation booking platform is developed following the example of Airbnb. In the requirements specification, required roles and user groups were analyzed together with the corresponding actions and permissions necessary for the platform to function properly. Based on the developed requirements a relational database is modeled in an entity relationship diagram and the data are described in detail in a data dictionary. The database has a high degree of normalization to reduce redundancy and improved storage efficiency. Three different types of entities are used to reach a high level of normalization: entity tables, mapping tables and reference tables. Technical primary keys are included to allow references from other tables as foreign keys.
The database was implemented using MySQL Workbench.
The SQL code is structured in four distinct files containing the create table and trigger statements, the insert statements for populating the database tables with dummy data and two kinds of test cases.
The create_tables.sql file contains the statements to create the database schema, the tables and triggers. The order of the tables is determined by the relationships of the tables, since FK relation-ships can only be created for already existing tables. Triggers are used to calculate the values for columns containing aggregations originating from other tables or to implement additional checks that couldn’t be added to the create table statement. Triggers in MySQL also have the beneficial property to be ACID compliant. RBAC is augmented by separating roles and permissions and im-plementing the mapping according to a role-permission-matrix. Where action is required on delete and on update statements are added to the tables. The populate_tables.sql file contains the insert statements for inserting data as well as an event that deletes expired availability periods from the availability table to keep up query performance by deleting irrelevant data from the schema.
The test cases are split into syntactic and semantic tests. Syntactic tests are considered those which test the correct functionality of the triggers and events, schema validity, and constraint viola-tion. For the latter exemplary tests are written that are expected to fail and could be analogously adapted to all tables and constraints. Semantic tests are supposed to test the logic and the rela-tionships of the database by joining tables to extract insights from the DB. Three perspectives in-volve most of the database tables: A user account is analyzed regarding its data as a guest (book-ings, payments, conversations), as a host (accommodations, bookings, conversations) and from a management perspective (address, roles, permissions and support tickets).

## Installation Process
In general the SQL scripts can be run in any environment that uses the MySQL dialect.
To set up the database in MySQL Workbench, download and install the software package for your operating system from the official [MySQL Workbench Website](https://dev.mysql.com/downloads/).
The component MySQL Server is required to run a local server and Workbench is required to create and edit schemas, tables and data in a UI or write SQL scripts.
After installation is complete, a new connection, e.g. with a local server can be set up and the 4 scripts from this repository can be opened and executed to create the database schema with tables, triggers, events, data and tests included.
Mind the order of script execition: create_tables.sql, populate_tables.sql, tests_syntactic.sql, tests_semantic.sql.

## Included Scripts
The create_tables.sql file creates tables in order determined by the relationships and dependencies between the tables. Triggers are created to allow calculated columns based on other tables.
The populate_tables.sql script fills all tables with randomly generated dummy data to. An event is added to delete expired data that is no longer needed. Therefore the event scheduler is turned on in this script.
The tests_syntactic.sql script contains technical tests that test the correct functionality of all triggers and events and exemplary tests for schema validity. Be aware the the syntactic tests contain three tests expected to fail for testing schema violations.
The tests_semantic.sql script contains a test case that covers the logical and relational aspects of the database. By viewing a user profile from three different perspectives an overview of the user data stored in the database is created. The test case covers the involved tables and tests the FK relationships by joining several tables together for each perspective.
